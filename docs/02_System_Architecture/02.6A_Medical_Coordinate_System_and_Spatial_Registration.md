# 1. Purpose

Medical visualization is fundamentally a spatial problem.

HybridBrainViz must preserve spatial consistency across:

- MRI acquisition
- segmentation
- mesh extraction
- volume rendering
- hybrid composition
- evaluation

The Spatial Framework defines coordinate systems, transformations, and
registration mechanisms required to ensure that every representation describes
the same anatomical structures.

-------------------------------------------------------------------------------

# 2. Spatial Framework Overview

The platform defines multiple coordinate spaces.

```text
Patient Space
      │
      ▼
Image Space
      │
      ▼
Voxel Space
      │
      ▼
World Space
      │
      ▼
Scene Space
      │
      ▼
Camera Space
      │
      ▼
Clip Space
      │
      ▼
Screen Space
```

Each space has a well-defined responsibility.

-------------------------------------------------------------------------------

# 3. Coordinate Systems

## 3.1 Patient Coordinate System

Represents the patient's anatomical orientation.

Supported conventions:

• LPS (Left–Posterior–Superior)

• RAS (Right–Anterior–Superior)

Patient Space is the highest-level anatomical reference.

-------------------------------------------------------------------------------

## 3.2 Image Coordinate System

Defines the physical geometry of the acquired MRI.

Contains:

- image origin
- orientation matrix
- voxel spacing
- image dimensions

Image coordinates preserve scanner geometry.

-------------------------------------------------------------------------------

## 3.3 Voxel Coordinate System

Represents discrete voxel indices.

Example:

(x, y, z)

Each voxel corresponds to one sample in the MRI volume.

Voxel coordinates are integer-based.

-------------------------------------------------------------------------------

## 3.4 World Coordinate System

World Space represents spatial positions using physical units (typically millimetres).

Voxel positions are transformed into World Space using image metadata.

World Space is shared by:

- surface meshes
- volume rendering
- clipping planes
- annotations

-------------------------------------------------------------------------------

## 3.5 Scene Coordinate System

The Scene Graph organizes entities in Scene Space.

Scene transforms are applied after conversion from World Space.

This enables camera manipulation without modifying medical data.

-------------------------------------------------------------------------------

## 3.6 Camera Coordinate System

Coordinates relative to the active camera.

Responsibilities:

- viewing transformations
- perspective projection
- clipping

-------------------------------------------------------------------------------

## 3.7 Screen Coordinate System

Final pixel coordinates after rendering.

Used for:

- GUI interaction
- picking
- annotation placement

-------------------------------------------------------------------------------

# 4. MRI Spatial Metadata

Each imaging volume stores:

- dimensions
- voxel spacing
- origin
- orientation
- affine transformation
- modality
- acquisition metadata

Spatial metadata accompanies the image throughout the workflow.

-------------------------------------------------------------------------------

# 5. Multi-Modal Registration

HybridBrainViz assumes that MRI modalities are spatially aligned before
visualization.

Typical modalities include:

- T1
- T1ce
- T2
- FLAIR

The platform preserves the registration relationship between modalities.

Future versions may include deformable or rigid registration pipelines.

-------------------------------------------------------------------------------

# 6. Transformation Hierarchy

The transformation chain is:

```text
Voxel Coordinates
        │
        ▼
Image Coordinates
        │
        ▼
World Coordinates
        │
        ▼
Scene Transform
        │
        ▼
View Matrix
        │
        ▼
Projection Matrix
        │
        ▼
Clip Coordinates
        │
        ▼
Screen Coordinates
```

Each transformation is represented as a 4×4 homogeneous matrix where appropriate.

-------------------------------------------------------------------------------

# 7. Spatial Representation of Segmentation

Segmentation maps are defined in the same voxel grid as the source MRI.

Each segmentation voxel corresponds to the same spatial location as the source
volume.

Supported regions include:

- Enhancing Tumor (ET)
- Tumor Core (TC)
- Whole Tumor (WT)
- Edema (ED)
- Necrosis (NCR)

The platform preserves one-to-one spatial correspondence between imaging and
segmentation data.

-------------------------------------------------------------------------------

# 8. Surface Mesh Spatial Mapping

Surface meshes generated by the Marching Cubes algorithm inherit the geometry
of the segmentation volume.

The workflow is:

```text
Segmentation Volume
        │
        ▼
Marching Cubes
        │
        ▼
Mesh Vertices (Voxel Space)
        │
        ▼
World Space Transformation
        │
        ▼
Scene Graph
```

No arbitrary scaling or translation is applied after extraction.

Mesh vertices remain anatomically aligned with the source MRI.

-------------------------------------------------------------------------------

# 9. Volume Rendering Space

GPU ray casting samples the MRI volume in texture space.

Sampling positions are transformed through:

```text
Texture Coordinates
        │
        ▼
Voxel Space
        │
        ▼
World Space
```

Transfer functions and gradient computations operate on spatially consistent
samples.

-------------------------------------------------------------------------------

# 10. Hybrid Visualization Alignment

Hybrid visualization combines:

- MRI volume
- surface mesh
- segmentation labels
- boundary overlays
- annotations

All representations share the same World Coordinate System.

This guarantees spatial consistency during compositing.

-------------------------------------------------------------------------------

# 11. Boundary Enhancement Spatial Model

The adaptive boundary-enhancement algorithm operates on spatially aligned data.

Inputs may include:

- gradient volume
- segmentation labels
- surface geometry
- rendered hybrid image

Boundary emphasis is computed using corresponding spatial locations rather than
independent image coordinates.

This ensures that highlighted boundaries accurately represent anatomical
interfaces.

-------------------------------------------------------------------------------

# 12. Camera and View Coordinates

The camera does not modify medical data.

Instead, it transforms the observer.

Supported camera operations:

- orbit
- pan
- zoom
- clipping
- reset
- predefined anatomical views

Camera movement is independent of domain objects.

-------------------------------------------------------------------------------

# 13. Precision and Numerical Stability

HybridBrainViz stores spatial data using floating-point precision suitable for
medical visualization.

Guidelines:

- preserve voxel spacing
- avoid repeated transform accumulation
- minimize coordinate conversion
- maintain consistent units (millimetres)
- avoid precision loss during mesh generation

-------------------------------------------------------------------------------

# 14. Spatial Validation

The platform validates spatial consistency throughout the workflow.

Validation checks include:

- MRI and segmentation dimensions match
- voxel spacing consistency
- affine transformation consistency
- mesh alignment with segmentation
- camera clipping correctness
- hybrid overlay alignment
- annotation placement accuracy

Validation failures prevent execution of dependent workflows.

-------------------------------------------------------------------------------

The Spatial Framework is designed to support:

- rigid registration

- ultrasound registration
- atlas-based visualization
- neuronavigation integration
- surgical planning
- longitudinal image alignment
- mixed-reality coordinate systems

-------------------------------------------------------------------------------

# Architectural Summary

The HybridBrainViz Spatial Framework establishes a unified geometric foundation
for all stages of the visualization pipeline. By preserving spatial metadata,
maintaining consistent coordinate transformations, and enforcing alignment
between imaging, segmentation, surface meshes, and volume rendering, the
platform ensures that hybrid visualizations remain anatomically faithful and
scientifically reproducible. This framework also provides the basis for future
multi-modal registration, advanced clinical visualization, and interoperable
medical imaging workflows.

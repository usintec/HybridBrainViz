# 1. Purpose

The Scene Graph represents the logical organization of all objects participating
in a visualization session.

It is responsible for:

- organizing scene entities,
- maintaining spatial relationships,
- storing visualization state,
- managing interaction metadata,
- supplying renderable content to the Render Graph.

The Scene Graph contains no GPU rendering logic.

-------------------------------------------------------------------------------

# 2. Scene Graph Philosophy

The Scene Graph answers one question:

**"What exists in the visualization?"**

It does not determine:

- GPU execution,
- rendering order,
- shader selection,
- graphics API calls.

These responsibilities belong to the Render Graph.

-------------------------------------------------------------------------------

# 3. Relationship to Other Graphs

HybridBrainViz employs three complementary graph systems.

```text
Scientific Workflow Graph
        │
        ▼
Generates Domain Objects
        │
        ▼
Scene Graph
        │
        ▼
Builds Render Requests
        │
        ▼
Render Graph
        │
        ▼
Graphics Abstraction Layer
```

Each graph operates at a different level of abstraction.

-------------------------------------------------------------------------------

# 4. Scene Graph Architecture

The Scene Graph consists of:

```text
Scene
│
├── Cameras
├── Lights
├── Volumes
├── Meshes
├── Hybrid Objects
├── Annotations
├── Measurements
├── Overlays
└── Helpers
```

Each object is represented as an entity with associated components.

-------------------------------------------------------------------------------

# 5. Entity–Component Model

Every scene object is an Entity.

Behavior and state are attached through Components.

Example:

```text
Tumor Entity
│
├── TransformComponent
├── MeshComponent
├── VolumeComponent
├── BoundaryComponent
├── MaterialComponent
├── VisibilityComponent
├── MetadataComponent
└── SelectionComponent
```

Entities are lightweight identifiers.

Components encapsulate reusable functionality.

-------------------------------------------------------------------------------

# 6. Scene Organization

Core entity categories include:

- Camera
- Light
- MRI Volume
- Tumor
- Segmentation Overlay
- Boundary Overlay
- Measurement
- Annotation
- Orientation Axes
- Clipping Plane
- Helper Objects

Relationships express logical grouping rather than rendering order.

-------------------------------------------------------------------------------

# 7. Scene Nodes

Every entity contains:

- Entity ID
- Name
- Parent (optional)
- Children (optional)
- Component Collection
- Tags
- Metadata

The hierarchy is used for transforms and logical grouping only.

-------------------------------------------------------------------------------

# 8. Components

Standard components include:

### TransformComponent

Position, rotation, scale, coordinate system.

### MeshComponent

References a SurfaceModel from the Domain Layer.

### VolumeComponent

References a VolumeRepresentation.

### BoundaryComponent

References boundary-enhancement data.

### SegmentationComponent

Stores label and region references.

### MaterialComponent

References visualization materials and transfer functions.

### VisibilityComponent

Controls visibility, opacity, and rendering layers.

### AnnotationComponent

Stores labels, notes, and measurements.

### MetadataComponent

Maintains dataset identifiers, acquisition details, and provenance.

### SelectionComponent

Tracks user selection and interaction state.

Components are composable and reusable.

-------------------------------------------------------------------------------

# 9. Transform System

Transforms are hierarchical.

Each TransformComponent contains:

- Local Transform
- World Transform
- Parent Transform
- Bounding Volume

Coordinate conversions preserve medical image geometry and voxel spacing.

-------------------------------------------------------------------------------

# 10. Visibility and Layering

Visibility is managed independently of rendering.

Supported layers include:

- MRI Volumes
- Surface Meshes
- Boundary Overlays
- Annotations
- Measurements
- Debug Helpers

Objects may belong to multiple logical layers where appropriate.

-------------------------------------------------------------------------------

# 11. Selection and Interaction

The Scene Graph supports interaction metadata for:

- entity selection
- picking
- highlighting
- clipping
- visibility toggling
- property editing

Interaction logic is consumed by the Presentation Layer.

-------------------------------------------------------------------------------

# 12. Scene Lifecycle

Typical lifecycle:

Create Entity

↓

Attach Components

↓

Insert into Scene

↓

Update Transforms

↓

Modify Visibility

↓

Remove Entity

↓

Release Resources

Scene entities are independent of GPU resource lifetimes.

-------------------------------------------------------------------------------

# 13. Integration with Hybrid Visualization

A hybrid brain tumor visualization is represented as a composition of components.

```text
Tumor Entity
│
├── MeshComponent
├── VolumeComponent
├── BoundaryComponent
├── SegmentationComponent
├── MaterialComponent
└── TransformComponent
```

The same entity can simultaneously reference surface, volume, and boundary representations.

-------------------------------------------------------------------------------

# 14. Integration with the Render Graph

The Scene Graph submits renderable entities to the Render Graph.

The Render Graph determines:

- render passes,
- resource allocation,
- execution order,
- synchronization.

The Scene Graph never invokes graphics APIs directly.

-------------------------------------------------------------------------------

# 15. Future Extensions

The Scene Graph is designed to support:

- multiple synchronized views,
- temporal imaging,
- longitudinal studies,
- collaborative annotations,
- VR/AR entities,
- surgical planning tools,
- radiomics overlays,
- radiogenomics visualization,
- multi-patient comparison.

-------------------------------------------------------------------------------

# Architectural Summary

The HybridBrainViz Scene Graph provides a logical, component-based representation of the visualization state. By separating scene organization from GPU execution and adopting an Entity–Component model, the architecture enables flexible composition of surface, volume, boundary, and annotation data while maintaining independence from rendering technologies. This design supports current hybrid brain tumor visualization requirements and provides a scalable foundation for future research and platform extensions.

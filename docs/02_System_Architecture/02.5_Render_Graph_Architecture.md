# 1. Purpose

The Render Graph coordinates GPU rendering within HybridBrainViz.

Its responsibilities are to:

- schedule rendering passes,
- manage GPU resources,
- resolve pass dependencies,
- optimize execution,
- provide backend-independent rendering.

The Render Graph does not perform visualization algorithms itself; it orchestrates their execution.

-------------------------------------------------------------------------------

# 2. Render Graph Philosophy

Rendering is modeled as a graph of render passes.

Each pass declares:

- required inputs,
- generated outputs,
- resource dependencies,
- execution order.

The graph is validated before execution and compiled into an optimized execution plan.

-------------------------------------------------------------------------------

# 3. Relationship to the Scientific Workflow Engine

HybridBrainViz contains two graph-based orchestration systems.

```text
Scientific Workflow Graph
        │
        ▼
Visualization Services
        │
        ▼
Render Graph
        │
        ▼
Graphics API
```

The Scientific Workflow Engine decides **what** operations occur.

The Render Graph decides **how** GPU rendering is executed.

-------------------------------------------------------------------------------

# 4. Scene Graph vs Render Graph

## Scene Graph

Represents logical scene content.

Examples:

- camera
- MRI volume
- surface mesh
- annotations
- lights

The Scene Graph is independent of rendering implementation.

--------------------------------------------------

## Render Graph

Represents GPU execution.

Examples:

- texture upload
- ray casting
- mesh rendering
- compositing
- post-processing

The Render Graph consumes Scene Graph data to produce images.

# 7. Render Passes

Each rendering operation is implemented as a RenderPass.

Standard lifecycle:

Initialize

↓

Acquire Resources

↓

Execute GPU Commands

↓

Publish Outputs

↓

Release Temporary Resources

↓

Complete

-------------------------------------------------------------------------------

## Standard Render Passes

### ClearPass

Clears color and depth targets.

--------------------------------------------------

### GradientComputationPass

Generates gradient volumes for illumination and boundary detection.

--------------------------------------------------

### VolumeRayCastingPass

Performs GPU ray casting of MRI volumes.

--------------------------------------------------

### MarchingCubesSurfacePass

Renders polygonal tumor meshes generated by the Surface Engine.

--------------------------------------------------

### HybridCompositionPass

Combines surface and volume representations into a single scene.

--------------------------------------------------

### BoundaryEnhancementPass

Applies the adaptive boundary-enhancement algorithm developed in this research.

Inputs may include:

- rendered volume
- rendered surface
- gradient magnitude
- segmentation labels
- boundary confidence map

Outputs:

- enhanced hybrid image

--------------------------------------------------

### AnnotationPass

Draws labels, axes, measurements, and clinical annotations.

--------------------------------------------------

### ToneMappingPass

Maps high dynamic range outputs to displayable color values.

--------------------------------------------------

### UIPass

Renders GUI overlays and interaction widgets.

# 8. Render Resources

Render resources are immutable handles managed by the Render Graph.

Examples:

MRITexture3D

GradientTexture3D

SegmentationTexture3D

SurfaceVertexBuffer

SurfaceIndexBuffer

DepthBuffer

ColorBuffer

BoundaryTexture

FinalFrame

Resources are reference-counted and automatically released when no longer required.

-------------------------------------------------------------------------------

# 9. Dependency Resolution

Each pass explicitly declares:

Required Inputs

Produced Outputs

Execution Dependencies

The graph compiler performs:

- dependency analysis,
- topological sorting,
- resource aliasing,
- redundant pass elimination.

Cycles are prohibited.

-------------------------------------------------------------------------------

# 10. GPU Resource Lifetime

Resources transition through four states.

```text
Created
    │
    ▼
Bound
    │
    ▼
Consumed
    │
    ▼
Released
```

The Render Graph manages resource lifetimes automatically.

-------------------------------------------------------------------------------

# 11. Synchronization

Synchronization is handled internally.

Responsibilities include:

- GPU barriers
- pass ordering
- resource state transitions
- framebuffer management

Higher layers never perform explicit synchronization.

# 13. Boundary Enhancement Integration

Boundary enhancement is implemented as a dedicated RenderPass.

Inputs:

- hybrid image
- gradient volume
- segmentation map
- optional confidence map

Operations:

- boundary detection
- adaptive enhancement
- edge weighting
- multi-modal blending

Outputs:

- boundary-enhanced hybrid visualization

Treating boundary enhancement as an independent pass allows alternative algorithms to be substituted without changing the rest of the rendering pipeline.

# Architectural Summary

The HybridBrainViz Render Graph is a backend-independent GPU orchestration framework that models rendering as a directed graph of render passes operating on managed GPU resources. By separating logical scene representation from GPU execution, the architecture enables efficient scheduling, resource optimization, parallel execution, and extensibility. This design provides a robust foundation for integrating hybrid surface and volume rendering with adaptive boundary enhancement while remaining adaptable to future graphics APIs and rendering techniques.

# 1. Purpose

This document defines how information flows through HybridBrainViz from raw
medical images to the final evaluated hybrid visualization.

It specifies:

- ownership
- lifecycle
- transformation
- persistence
- disposal

for every major data object.

-------------------------------------------------------------------------------

# 2. Architectural Philosophy

Every piece of data has:

• an owner

• a lifecycle

• a transformation history

• immutable versions

• traceability

The architecture follows a data-centric approach where scientific information
flows through well-defined stages without losing provenance.

-------------------------------------------------------------------------------

# 5. Runtime Object Lifecycle

Runtime objects exist only while the application is executing.

```text
Create

↓

Initialize

↓

Register

↓

Use

↓

Release

↓

Destroy
```

Examples include:

- Scene entities
- Cameras
- Workflow contexts
- Command objects
- Query DTOs
- Temporary buffers

-------------------------------------------------------------------------------

# 6. GPU Resource Lifecycle

GPU resources are managed independently of domain objects.

```text
Allocate

↓

Upload

↓

Bind

↓

Render

↓

Unbind

↓

Release
```

Examples:

- 3D textures
- Vertex buffers
- Index buffers
- Uniform buffers
- Shader programs
- Framebuffers
- Compute buffers

GPU resources never own scientific data.

-------------------------------------------------------------------------------

# 7. Ownership Model

Every object has exactly one owner.

| Object | Owner |
|----------|---------------------------|
| Dataset | Dataset Manager |
| MultiModalVolume | Imaging Repository |
| SegmentationResult | Segmentation Repository |
| SurfaceModel | Surface Service |
| VolumeRepresentation | Volume Service |
| HybridScene | Scene Manager |
| Experiment | Experiment Repository |
| EvaluationReport | Evaluation Service |

Ownership transfers are explicit.

# 9. Data Immutability

Scientific data objects are immutable after publication.

Example:

```text
MRI Volume

↓

Segmentation

↓

New SegmentationResult
```

The original MRI volume is never modified.

Similarly:

```
SurfaceModel V1

↓

Mesh Simplification

↓

SurfaceModel V2
```

Each transformation creates a new version.

-------------------------------------------------------------------------------

# 10. Pipeline State Transitions

Each workflow node receives immutable inputs and produces immutable outputs.

```text
Input

↓

Validate

↓

Process

↓

Generate Output

↓

Publish Output
```

Nodes never modify upstream resources.

# 13. Memory Management

Memory ownership follows RAII principles.

Guidelines:

- automatic destruction
- smart pointers
- shared ownership only where required
- deterministic cleanup
- avoid raw owning pointers

Temporary objects should have the shortest possible lifetime.

-------------------------------------------------------------------------------

# 14. Error Recovery

Failures do not invalidate upstream data.

Example:

```text
Surface Generation Failed

↓

SurfaceModel not created

↓

SegmentationResult remains valid

↓

Workflow may retry
```

This ensures robustness and reproducibility.

# Architectural Summary

The Data Flow and Lifecycle Architecture defines how scientific information,
runtime objects, and GPU resources evolve throughout HybridBrainViz. By assigning
clear ownership, enforcing immutable scientific artifacts, separating runtime and
GPU lifecycles, and preserving complete provenance, the platform ensures
reproducible research, robust execution, and maintainable software evolution.

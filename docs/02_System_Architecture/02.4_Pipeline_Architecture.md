# 1. Purpose

The Scientific Workflow Engine (SWE) is responsible for orchestrating all computational workflows within HybridBrainViz.

Unlike a traditional linear pipeline, the SWE executes workflows represented as Directed Acyclic Graphs (DAGs), enabling parallel execution, modular composition, reproducibility, and extensibility.

The engine coordinates imaging, AI inference, visualization, evaluation, and reporting without embedding domain-specific algorithms.

-------------------------------------------------------------------------------

# 2. Scientific Workflow Philosophy

HybridBrainViz treats visualization as a scientific workflow rather than a rendering sequence.

A workflow may include:

- MRI loading
- preprocessing
- segmentation
- mesh extraction
- volume rendering
- hybrid composition
- boundary enhancement
- evaluation
- report generation

Each stage is represented as an independent node with explicit inputs and outputs.

-------------------------------------------------------------------------------

# 3. Why a DAG-Based Workflow

Linear pipelines are insufficient because:

- Surface and volume rendering can execute independently.
- Evaluation may consume multiple upstream results.
- New algorithms should be insertable without rewriting existing flows.
- Multiple experiments should reuse common workflow fragments.

A Directed Acyclic Graph provides:

- deterministic execution
- dependency awareness
- branch and merge operations
- parallel scheduling
- reusable subgraphs

# 6. Workflow Nodes

Every computation is encapsulated as a WorkflowNode.

Standard node lifecycle:

Initialize

↓

Validate Inputs

↓

Acquire Resources

↓

Execute

↓

Publish Outputs

↓

Release Resources

↓

Complete

Each node exposes:

- Node ID
- Name
- Version
- Input Ports
- Output Ports
- Configuration
- Dependencies
- Metadata

-------------------------------------------------------------------------------

# 7. Workflow Edges

Edges define data and execution dependencies.

Edge types include:

- Data Edge
- Control Edge
- Conditional Edge (future)
- Event Edge (future)

Edges are directional and cycles are prohibited.

-------------------------------------------------------------------------------

# 8. Scheduler

The Scheduler is responsible for:

- topological sorting
- dependency resolution
- parallel task identification
- resource-aware scheduling
- retry policies
- execution ordering

Scheduling decisions are deterministic for identical workflow definitions.

-------------------------------------------------------------------------------

# 9. Executor

The Executor performs node execution.

Responsibilities:

- create execution context
- invoke node implementations
- capture outputs
- collect timing information
- propagate failures
- publish workflow events

Execution is independent of rendering and AI implementations.

-------------------------------------------------------------------------------

# 10. Execution Context

ExecutionContext contains:

- experiment identifier
- dataset references
- configuration snapshot
- random seed
- GPU selection
- thread pool
- logger
- service registry
- cancellation token
- progress reporter

The context is passed to every node and remains immutable except for runtime state explicitly designed to evolve (e.g., progress).

-------------------------------------------------------------------------------

-------------------------------------------------------------------------------

# 14. Validation

Before execution, the graph is validated for:

- cycles
- disconnected nodes
- incompatible resource types
- duplicate identifiers
- missing dependencies
- missing required configuration

Invalid workflows cannot execute.

-------------------------------------------------------------------------------

# 15. Serialization

Workflow definitions are serializable.

Supported formats:

YAML (primary)

JSON (secondary)

Serialized workflows include:

- graph topology
- node configuration
- plugin versions
- parameter values
- execution metadata

This enables exact experiment reproduction.

-------------------------------------------------------------------------------

# 16. Parallel Execution

Independent branches execute concurrently when resources permit.

Example:

```text
           Segmentation
                 │
        ┌────────┴────────┐
        ▼                 ▼
 Marching Cubes     Volume Ray Casting
        │                 │
        └────────┬────────┘
                 ▼
        Hybrid Composition
```

The Scheduler identifies independent branches automatically.

-------------------------------------------------------------------------------

# 17. Failure Recovery

Node failures are isolated.

Policies include:

- retry
- skip (configurable)
- abort workflow
- rollback (where applicable)

All failures are logged and associated with the current ExperimentRun.

-------------------------------------------------------------------------------

# 18. Experiment Reproducibility

Every execution records:

- workflow definition
- software versions
- plugin versions
- dataset identifiers
- configuration snapshot
- execution timestamps
- hardware information
- evaluation outputs

This ensures scientific reproducibility.

# Architectural Summary

The Scientific Workflow Engine provides a graph-based orchestration framework for HybridBrainViz. By representing experiments as validated Directed Acyclic Graphs composed of immutable resources and pluggable workflow nodes, the platform achieves modularity, parallel execution, reproducibility, and long-term extensibility. This architecture aligns scientific experimentation with modern workflow orchestration principles while remaining independent of graphics APIs, AI frameworks, and presentation technologies.

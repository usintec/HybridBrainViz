# 1. Purpose

This document defines the logical layers that compose the HybridBrainViz platform.

Each layer has:

- clearly defined responsibilities,
- explicit ownership,
- dependency rules,
- visibility rules,
- interface contracts,
- extension mechanisms.

The layered architecture exists to maximize:

• maintainability

• extensibility

• portability

• testability

• scalability

• scientific reproducibility

-------------------------------------------------------------------------------

# 2. Architectural Overview

HybridBrainViz consists of eight architectural layers.

```

```
+-----------------------------------------------------------+
|                 Presentation Layer                        |
+-----------------------------------------------------------+
|                 Application Layer                         |
+-----------------------------------------------------------+
|                   Pipeline Layer                          |
+-----------------------------------------------------------+
|                    Domain Layer                           |
+-----------------------------------------------------------+
|                Visualization Layer                        |
+-----------------------------------------------------------+
|                   Graphics Layer                          |
+-----------------------------------------------------------+
|                Infrastructure Layer                       |
+-----------------------------------------------------------+
|                    Platform Layer                         |
+-----------------------------------------------------------+
```

Dependencies flow downward only.

Higher layers may depend upon lower layers.

Lower layers must never depend upon higher layers.

-------------------------------------------------------------------------------

# 3. Dependency Rule

Allowed

```
Presentation
      ↓
Application
      ↓
Pipeline
      ↓
Domain
      ↓
Visualization
      ↓
Graphics
      ↓
Infrastructure
      ↓
Platform
```

Forbidden

```
Graphics → Application

Graphics → Presentation

Domain → UI

Pipeline → Desktop

Infrastructure → Visualization

Platform → Domain
```

Circular dependencies are prohibited.

# 4. Layer Responsibilities

## Layer 1

Presentation Layer

Purpose

Provides user interaction.

Examples

Desktop Application

CLI

Python API

REST API

Future Web Application

Responsibilities

Receive user requests

Display rendered scenes

Present evaluation reports

Handle interaction

The Presentation Layer contains no business logic.

-------------------------------------------------------------------------------

## Layer 2

Application Layer

Purpose

Coordinates system behavior.

Responsibilities

CQRS-lite

Commands

Queries

Workflow orchestration

Transactions

Session management

Experiment execution

The Application Layer never performs rendering.

-------------------------------------------------------------------------------

## Layer 3

Pipeline Layer

Purpose

Coordinates scientific workflows.

Responsibilities

Pipeline Builder

Execution Planner

Scheduling

Dependency Resolution

Progress Tracking

Pipeline Events

Scientific workflows are represented as executable graphs.

-------------------------------------------------------------------------------

## Layer 4

Domain Layer

Purpose

Represents scientific knowledge.

Contains

PatientStudy

VolumeData

MRISequence

SegmentationResult

SurfaceMesh

HybridScene

Experiment

EvaluationResult

The Domain Layer contains no OpenGL code.

-------------------------------------------------------------------------------

## Layer 5

Visualization Layer

Purpose

Transforms domain data into visual representations.

Contains

Surface Engine

Volume Engine

Hybrid Engine

Boundary Enhancement

Transfer Functions

Scene Construction

This layer knows nothing about Qt or desktop windows.

-------------------------------------------------------------------------------

## Layer 6

Purpose

Contains

Render Graph

Camera

Shaders

Materials

Textures

Meshes

Lighting

Framebuffers

## Layer 7

Purpose

Provides reusable technical services.

Contains

Logging

Serialization

Dependency Injection

Plugin Manager

Event Bus

Filesystem

Asset Loader

Thread Pool

Database (future)

## Layer 8

Contains

OpenGL

Vulkan

DirectX

Metal

CUDA

Filesystem APIs

Windowing

| Layer | Owns |
|---------|-------------------------|

# 6. Communication Rules

Presentation communicates only with Application.

Application communicates only with Pipeline.

Pipeline communicates with Domain.

Visualization consumes Domain objects.

Graphics consumes visualization commands.

Infrastructure provides shared services.

Platform provides native capabilities.

-------------------------------------------------------------------------------

Every layer exposes interfaces.

Example

↓

IExperimentService

↓

Application

↓

IPipelineExecutor

↓

Pipeline

↓

IVisualizationPipeline

↓

Visualization

↓

IGraphicsDevice

↓

Graphics
```

Concrete implementations never cross architectural boundaries.

-------------------------------------------------------------------------------

# 8. Data Ownership

Domain objects are immutable wherever practical.

Visualization never modifies MRI data.

Graphics never modifies segmentation data.

Evaluation never modifies visualization.

Presentation never modifies domain entities directly.

-------------------------------------------------------------------------------

# 9. Dependency Injection

Every dependency is resolved through the Service Registry.

Example

```
HybridRenderer

↓

IVolumeRenderer

ISurfaceRenderer

IBoundaryEnhancer

```

No class should instantiate collaborators using `new` except within the composition root during application startup.

-------------------------------------------------------------------------------

# 11. Runtime Rules

At runtime

Presentation starts Application.

Application starts Pipeline.

Pipeline executes workflows.

Visualization builds render requests.

Graphics executes GPU commands.

Infrastructure supplies shared services.

Platform executes native APIs.

# 13. Extensibility

New rendering algorithms belong only in Visualization.

New graphics APIs belong only in Platform (with corresponding Graphics adapters).

New AI models belong in the Segmentation subsystem within the Visualization/Application boundary, exposed through interfaces.

New desktop interfaces belong only in Presentation.

No existing layer should require redesign when a new feature is added.

-------------------------------------------------------------------------------

# 14. Architectural Invariants

The following rules are mandatory:

✓ No circular dependencies.

✓ No UI code outside Presentation.

✓ No OpenGL/Vulkan code outside Graphics and Platform.

✓ No scientific logic inside Presentation.

✓ No rendering code inside Domain.

✓ No application logic inside Graphics.

✓ No hardcoded implementations where an interface is expected.

✓ Every module must be replaceable.

-------------------------------------------------------------------------------

# 15. Architectural Summary

The HybridBrainViz layered architecture separates concerns into independent, cohesive layers with clear responsibilities and one-way dependencies. This structure enables the platform to evolve from a desktop research application into a reusable, multi-backend ecosystem while preserving maintainability, extensibility, and scientific reproducibility.
